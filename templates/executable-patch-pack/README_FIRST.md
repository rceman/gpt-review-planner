# Read First

`AGENT_HANDOFF.md` is the only normative execution entry point. `AGENT_PROMPT.md` is not generated by the canonical template. A one-release compatibility alias may be supplied only when it is byte-identical to `AGENT_HANDOFF.md`.

## Patch identity

The generator writes patch, workflow, target, base, and evidence-directory identity into both `manifest.json` and `AGENT_HANDOFF.md`. Divergence is invalid.

## Template state versus ready state

A newly generated directory is template state. It is intentionally invalid for delivery while requirements, gates, evidence IDs, patch/overlay/delete payload, validation truth, or handoff instructions remain incomplete.

Ready-for-delivery state requires:

1. complete behavior, patch specification, tests, fixtures, and implementation payload;
2. non-empty manifest requirements and gates;
3. pending evidence entries with exactly matching IDs and order;
4. exact manifest/patch/overlay/delete scope;
5. canonical `AGENT_HANDOFF.md` headings and manifest identity;
6. no unresolved placeholders;
7. byte-identical bundled planner tools;
8. semantic and delivery validation.

## Required order

1. Read the target repository's `AGENTS.md` and `.gpt-workflow.lock`.
2. Read `AGENT_HANDOFF.md` and the complete patch pack.
3. Verify repository identity, branch, and base revision.
4. Apply the supplied implementation rather than reimplementing it from prose.
5. Restore dependencies and run every required runtime gate.
6. Correct only verified narrow integration defects and add regression coverage.
7. Keep final file operations exactly equal to `manifest.json`.
8. Create the implementation commit followed by the exact two-file evidence commit.
9. Run `scripts/verify-agent-result.sh` in prepare and committed modes.
10. Return the required English execution report without merging or releasing.
